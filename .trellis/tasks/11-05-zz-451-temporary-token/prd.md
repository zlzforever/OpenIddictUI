# PRD：只读临时访问令牌

状态：修订版已获用户确认；编号 ZZ-450。

## 背景与目标

将已有访问令牌代表的有限访问能力短时分享给可信的外部人员，用于调用现有业务 API。首版提供签发 API 和仓库内示例接入，不提供分享页面或分享渠道。

## 需求

1. **申请凭据**：仅接受本系统签发、有效的 JWT access token，通过 Bearer 方式提交。不区分用户与服务身份；仅有登录 Cookie 不足以申请。不接受第三方 JWT、ID token 或临时令牌。无需为区分真实用户而引入新来源标记，也不因缺少该标记拒绝旧令牌。
2. **内容与权限**：以经过验证的原 JWT 为基础，保留来源身份、角色及其他业务声明的原值和结构，不查询数据库补充权限，不从请求参数注入身份或角色。新令牌需重设自身的签发时间、到期时间和令牌标识，并添加受签名保护的只读标记；scope 可按第 3 条缩小，audience 必须满足第 3 条的范围限制。若业务声明与必需标记冲突，或无法安全保留，拒绝签发，不能静默丢弃或扩大权限。业务 API 仍须执行原有授权和数据权限检查。
3. **Scope 与目标**：默认使用来源 JWT 的完整 scope；申请方可明确请求其中的子集，不得请求超集。可分享的 scope、目标 API 及其 audience 由服务端配置；签发目标不得超出来源令牌的 audience 和服务端许可范围。未配置或不满足限制时拒绝；默认的完整 scope 不全部符合配置时明确拒绝，调用方可请求允许的子集，不静默缩减。
4. **有效期与复用**：有效期至多 5 分钟，且不超过来源 JWT 的到期时间；过期后不可使用。有效期内可多次使用；不签发 refresh token，也不能用临时令牌申请新的临时令牌。
5. **只读标记与执行**：临时 JWT 带服务端签名保护的、可识别的只读标记。接收方必须识别标记，并在业务授权时只允许读取、拒绝修改及无法明确判定安全性的操作。判断依据是实际业务操作，而不是简单假设所有 GET 都安全或所有 POST 都写入。
6. **失效与分享**：首版依靠令牌到期，不承诺退出登录、账号禁用或主动撤销后立即失效。持有人在有效期内可以读取来源身份在所选 API 中原本有权读取的数据；不限定单条记录、设备或收件人。Bearer 令牌可被转发，应只分享给可信对象。
7. **交付方式**：签发 API 返回临时访问令牌及到期时间；不将令牌放入 URL 或日志，不提供页面。接口路径、参数和响应字段在规划阶段确定，并遵循项目现有 API 约定。

## 安全边界与示例范围

- 签发时必须验证来源令牌的签名、可信签发方、有效期、access token 用途及允许的目标；仅解析 JWT 内容不足以通过认证。缺少必要 scope、audience 或授权依据时拒绝签发。
- 首版以仓库示例 `api1` 为演示，修改示例 API 使其正确验证 issuer、audience 和 scope，并示范临时令牌只读授权。调整时验证普通合法访问令牌的兼容性。
- 生产环境默认不开放可分享目标。管理员须明确配置 scope 与 audience，并确认所有可能接收该 audience 的业务服务均已验证令牌并实施只读策略，才能启用该目标。其他业务 API 由各自负责人改造。
- **重要限制**：签发端白名单和 JWT 标记本身不能阻止持有人把令牌发给忽略标记、受众校验过宽或复用同一 audience 的 API；这些服务仍可能允许写入。不能将未完成只读接入的服务视为已受保护，也不能宣称系统全局已强制只读。
- 令牌应通过受保护的传输方式分享；签发响应不得被缓存，日志和错误信息不得泄露来源或临时令牌。

## 验收标准

1. 符合策略的合法来源 JWT，无论代表用户还是服务身份，均可签发临时 JWT。来源身份、角色和其他业务声明按上述规则保留且不增权；默认 scope 与来源一致，请求子集时只授予该子集，audience 不越过来源及服务端配置。测试覆盖角色和自定义业务声明的值及结构。
2. 来源 scope 超集请求、未配置目标或 audience 不匹配均被拒绝；默认完整 scope 不在许可范围时不静默扩权或缩减。仅 Cookie、第三方 JWT、ID token、过期或签名无效的令牌及临时令牌申请均被拒绝；旧令牌不因缺少用户来源标记被拒绝，但仍须满足其他验证和策略要求。
3. 自动化测试验证临时令牌带可验证的只读标记、不返回 refresh token、不能链式签发，且到期时间不超过签发时起 5 分钟或来源 JWT 到期时间。过期令牌被拒绝。
4. 示例 API 的自动化测试覆盖：临时令牌在授权范围内可多次读取；写入及未明确分类的操作被拒绝；错误 issuer、audience、scope 被拒绝；普通有效令牌的既有授权行为仍可用。测试使用可观察的受保护写操作或等价测试端点，不依赖真实业务数据被修改。
5. 文档说明配置方法、申请与示例调用、只读接入责任、Bearer 可转发风险和无法立即撤销的限制，不含真实凭据。

## 非目标

不提供 Cookie 直接申请、前端页面、一次性或绑定收件人的令牌、记录级分享、实时撤销，也不自动改造仓库外业务 API。
